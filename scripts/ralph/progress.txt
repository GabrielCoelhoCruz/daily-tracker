## Codebase Patterns
- Expo SDK 55 with Expo Router file-based routing (`app/` directory)
- NativeWind v4 with Tailwind CSS for styling (`className` prop on RN components)
- Custom Tailwind colors in `tailwind.config.js`: bg-primary (#0c0a09), bg-card (#1c1917), bg-elevated (#292524), accent (#f59e0b), txt-primary (#fafaf9), txt-secondary (#a8a29e), txt-muted (#78716c)
- `constants/theme.ts` exports `theme` object with all color tokens + `typography` (caption, footnote, body, callout, headline, title3) — use for inline styles
- `@/` path alias for project root imports
- `npx tsc --noEmit` for typecheck
- Zustand stores in `stores/` with persist middleware + AsyncStorage — see `useConfigStore.ts` for pattern
- NativeWind `className` for static layout styles, inline `style` for dynamic colors and typography
- Tab bar in `app/(tabs)/_layout.tsx` uses `NativeTabs` from `expo-router/unstable-native-tabs` with SF Symbols (iOS) + `VectorIcon` fallbacks (Android). Requires `react-native-screens ~4.16.0` on SDK 54.
- Liquid Glass in Expo Go (no dev build): use `expo-glass-effect` (`GlassView`) + `expo-blur` fallback via `hooks/useShouldRenderGlass.ts`; NEVER static-import `@expo/ui/swift-ui/modifiers` (crashes Expo Go at module load).
- Native stack headers: `constants/stackScreenOptions.ts` exports `tabStackScreenOptions` (transparent + large title), `glassSheetScreenOptions`, `detailStackScreenOptions`. Tab layouts set `headerRight: () => <SettingsHeaderButton />`.
- In-app icons: `components/ui/AppIcon.tsx` — SF Symbol via `expo-symbols` on iOS, MaterialCommunityIcons on Android.
- Glass UI primitives: `GlassChip` (status/actions), `GlassButton` (circular header actions). Sheets use `contentStyle: { backgroundColor: "transparent" }` for iOS 26 glass backgrounds.
- Tab badge: `hooks/usePendingDashCount.ts` feeds `<Badge>` on Dash tab in NativeTabs.
- All other components use `MaterialCommunityIcons` from `@expo/vector-icons/MaterialCommunityIcons` (default import, NOT named import)
- Route structure: `app/(tabs)/(hoje)/index.tsx`, `(treino)/index.tsx`, `(historico)/index.tsx`, `(progresso)/index.tsx`
- Sub-routes use formSheet presentation: `presentation: 'formSheet'`, `sheetGrabberVisible: true`, `sheetAllowedDetents: [0.5, 1.0]`
- All screens use ScrollView as first child with `contentInsetAdjustmentBehavior="automatic"`
- `<Card>` component in `components/ui/Card.tsx` — always use for card-style containers
- `<Card className="p-0">` when component manages own internal padding
- Screen content gaps use `gap-3` (12px) between cards
- Settings/nav buttons go in `headerRight` of Stack.Screen options
- Use `minHeight: 44` via inline `style` for touch target compliance
- `npm install --legacy-peer-deps` required due to react-native-web peer dependency conflict with React 19
- `process.env.EXPO_OS === "ios"` for iOS-only code (not Platform.OS)
- `borderCurve: 'continuous'` for iOS squircle corners — must be inline style, not NativeWind
- expo-file-system SDK 55: use `File`/`Directory`/`Paths` from root import; legacy API at `/legacy` throws at runtime
- Use `file.base64()` instead of `readAsStringAsync` with `EncodingType.Base64`
- Typed routes: use `as any` cast for new route groups not yet in generated types
- Physique feature files: `(progresso)/_layout.tsx`, `index.tsx`, `new-checkin.tsx`, `result.tsx`, `PhotoSlots.tsx`, `usePhysiqueStore.ts`, `physiqueAnalysis.ts`, `api.ts`
- Product prompt reference: `docs/physique-check-product-prompt.md` — source of truth for all category data
- Expo API Routes: use standard `Request`/`Response` (not ExpoRequest/ExpoResponse), file suffix `+api.ts` in `app/` dir
- CATEGORY_LABELS exists in BOTH `usePhysiqueStore.ts` AND `physiqueAnalysis.ts` — update both when adding categories
- `useAthleteStore.getState()` for reading athlete data outside React components (e.g., in service files)
- Liquid Glass experiment (branch experiment/liquid-glass-swiftui): `@expo/ui` SwiftUI works on SDK 54, beta package `@expo/ui@0.2.0-canary`. Imports: `@expo/ui/swift-ui` (Host, HStack, Text, etc.) and `@expo/ui/swift-ui/modifiers` (glassEffect, padding, foregroundStyle, font, cornerRadius). `glassEffect({ glass: { variant: 'regular' }, shape: 'capsule' })` requires iOS 26+; no-op on earlier iOS. `Text` from `@expo/ui/swift-ui` does NOT accept `style` — use `foregroundStyle`/`font` modifiers instead (use `Text as RNText` from react-native for fallback UI). `@expo/ui` does NOT work in Expo Go — requires `expo-dev-client` (dev build). EAS dev build for SDK 54 must pin `ios.image: "macos-sequoia-15.6-xcode-26.0"` in eas.json to compile SwiftUI. First iOS internal-distribution build requires INTERACTIVE Apple ID login to set up credentials — `--non-interactive` fails until credentials exist (run `eas build -p ios --profile development` once interactively, or `eas credentials`).
- `isProfileComplete()` is a Zustand getter — call as function: `useAthleteStore((s) => s.isProfileComplete)()`

## 2026-06-26 - Liquid Glass experiment PAUSED (no Apple Developer account)
- **Decision**: validating Liquid Glass on a physical iPhone requires a paid Apple Developer Program membership (US$ 99/yr) to sign the ad-hoc `.ipa`. EAS Build free tier covers build infra but cannot bypass Apple's signing requirement. Without the paid account, the iOS dev build cannot be installed on the device, so the glass effect cannot be visually validated.
- **Fix to keep branch bootable in Expo Go**: `@expo/ui/swift-ui/modifiers` calls `requireNativeModule('ExpoUI')` at module top level → throws in Expo Go (no native module) → crashed the Hoje route on boot (`Cannot find native module 'ExpoUI'` + `Route ... missing default export`). Added runtime guard in `components/ui/GlassChip.tsx`: only `require("@expo/ui/...")` when `NativeModules.ExpoUI` is present (dev/prod build). In Expo Go the chip renders the solid fallback. Commit `eab34f0`.
- **Current state**: branch `experiment/liquid-glass-swiftui` is stable in Expo Go (solid fallback chip on Hoje). `npx tsc --noEmit` clean.
- **To resume later**: get an Apple Developer Program membership, then run `eas device:create` (register iPhone UDID) and `eas build --profile development --platform ios` interactively (Apple ID + 2FA), install the `.ipa` on iOS 26, `npx expo start --dev-client`. The SwiftUI glass path is already wired and will activate automatically once `NativeModules.ExpoUI` is present and iOS >= 26.
- **Learnings for future iterations:**
  - EAS Build free tier is enough for build infrastructure, but iOS **physical device** install always needs a **paid** Apple Developer account (ad-hoc provisioning). Free Apple account only allows simulator builds (needs Mac/Xcode) or 7-day Xcode-signed dev builds — neither works on Windows + iPhone.
  - Android dev build (`eas build --profile development --platform android` → `.apk`) is fully free and installable on a physical device, but Liquid Glass is iOS-only so it doesn't validate the glass — only the dev-build mechanics.
  - `requireNativeModule('ExpoUI')` runs at module load, so a `Platform` check inside a component is NOT enough to guard `@expo/ui` in Expo Go — must guard the `require()` itself via `NativeModules.ExpoUI` existence check.
